# GP32emu 사용설명서

Windows 독립 실행 프로그램과 RetroArch용 GP32 코어의 설치·조작·저장 안내입니다.
BIOS와 게임 파일은 포함하지 않습니다. 직접 보유한 덤프를 사용하세요.

## 필요한 파일

| 대상 | ZIP 패키지와 루트의 실행 파일 |
| --- | --- |
| Windows x64 독립 실행 | `gp32emu-1.0.0-windows-x64.zip`: `gp32emu_win64.exe`, `SDL3.dll` |
| Windows x64 RetroArch | `gp32emu-1.0.0-libretro-windows-x64.zip`: `gp32emu_libretro.dll` |
| Linux AArch64 RetroArch | `gp32emu-1.0.0-linux-aarch64.zip`: `gp32emu_libretro.so` |
| Android 앱 | `gp32emu-1.0.0-android.apk`: 별도 설치, RetroArch 불필요 |
| Android ARM64 RetroArch | `gp32emu-1.0.0-android-arm64.zip`: `gp32emu_libretro_android.so` |
| Android ARMv7 RetroArch | `gp32emu-1.0.0-android-armv7.zip`: `gp32emu_libretro_android.so` |

각 코어 ZIP에는 `gp32emu_libretro.info`도 포함되어 있습니다. 모든 ZIP에는 README,
릴리스 노트, 이 설명서, `licenses/`, `manifest.json`이 함께 들어 있습니다.
Linux 코어는 glibc 2.17 이상, Android 코어는 API 21 이상을 대상으로 합니다.
Android 앱은 Android 6.0 이상이 필요합니다. 실제 ARM 휴대전화 검증은 아직 남아 있습니다. ARMv7은 JIT 없이 동작하므로
ARM64보다 상당히 느립니다.

게임은 `.smc` 카드 이미지와 `.fxe`, `.fpk` 형식을 엽니다. GP32 BIOS는 512 KiB 이하라면
어느 덤프든 사용할 수 있고, 파일 이름은 `gp32166m.bin`을 권장합니다. BIOS 없이 실행할
수 있는 게임은 제한되어 있습니다.

## Windows 독립 실행

1. 압축을 풀고 `gp32emu_win64.exe`와 `SDL3.dll`을 같은 폴더에 둡니다.
2. 프로그램을 처음 실행하면 BIOS를 고를지 묻습니다. 나중에 `설정 > BIOS 지정...`에서
   바꿀 수 있습니다.
3. `파일 > 게임 열기...`, `파일 > 게임 목록...`, `파일 > 최근 게임`으로 게임을 열거나
   SMC·FXE·FPK 파일을 창에 끌어다 놓습니다.

메뉴와 대화상자는 Windows 표시 언어를 따라 한국어나 영어로 나옵니다. 언어를 고정하려면
`GP32emu.ini`의 `[UI]` 항목에 `Language=ko` 또는 `Language=en`을 적습니다.

설정, 상태 저장, 스크린샷, 녹화 파일은 실행 파일 옆의 `GP32emu.ini`와 `states`,
`screenshots`, `recordings` 폴더에 저장하므로 쓰기 가능한 폴더에 두세요.
`게임 목록`에서 `폴더 선택...`으로 게임 폴더 하나를 등록하면 목록에서 게임을 두 번 클릭해
실행할 수 있습니다. 해당 폴더 바로 아래의 SMC·FXE·FPK만 표시하며, 하위 폴더와 저장 파일은
제외합니다. ZIP은 먼저 압축을 풀어 주세요. 파일을 추가했다면 `새로 고침`을 누르세요.
최근 게임은 8개까지 기억합니다.
BIOS 없이 실행하면 HLE 대체 실행을 사용합니다. 이 방식으로 시작하지 못하는 게임은 BIOS를
지정해서 실행하세요. `설정 > BIOS 없이 게임 실행 허용`을 끄면 BIOS가 있어야만 실행합니다.

`에뮬레이션` 메뉴에서 일시정지, 리셋, 빨리 감기, JIT 사용 여부를 바꿉니다.
`비디오`에서 창 크기(1~4배), 전체 화면, 4:3 비율 유지·정수배 확대·창에 맞게 늘이기,
LCD 잔상 효과, 프레임 블렌딩을 고릅니다. 화면 출력에 문제가 있으면 `렌더러`에서
`GDI (호환 모드)`를 선택하세요. `오디오`에서는 `waveOut`, `WASAPI 공유`,
`WASAPI 독점`을 선택합니다. 게임이 실행 중일 때만 쓸 수 있는 메뉴는 그 전까지 흐리게 표시됩니다.

### 키보드와 단축키

| 키 | 동작 |
| --- | --- |
| 방향키 | GP32 방향키 |
| Z / X | GP32 A / B |
| A / S | GP32 L / R |
| Enter | Start |
| Shift | Select |
| F5 / F8 | 현재 슬롯에 상태 저장 / 불러오기 |
| F6 / F7 | 이전 / 다음 상태 슬롯 (1~9) |
| F9 | 일시정지 / 재개 |
| Tab (누르고 있기) | 빨리 감기. 이때 소리는 꺼짐 |
| F12 | 스크린샷을 `screenshots` 폴더에 저장 |
| F11 또는 Alt+Enter | 전체화면 전환 |
| Esc | 전체화면이면 창 모드로 전환. 프로그램을 종료하지 않음 |

위 표는 기본 배치입니다. `설정 > 키보드 설정...`에서 바꿀 버튼을 클릭하고
새 키를 누른 뒤 `확인`을 선택하면 저장됩니다. 이미 쓰는 키를 지정하면 두 버튼의 키를
서로 바꿉니다. `기본값`은 기본 배치를 복원하고 `취소`는 변경을 버립니다.
키 입력 대기 중 Esc는 해당 입력을 취소합니다. Esc·Tab·Alt·Windows 키와
F5~F12는 창 조작과 단축키용으로 예약되어 있습니다. 현재 배치는
`도움말 > 조작법과 단축키`에서 볼 수 있습니다.
종료는 창 닫기 버튼, `파일 > 종료` 또는 Alt+F4를 사용하세요.

게임패드는 연결하면 바로 인식합니다. 방향 패드나 왼쪽 스틱이 방향, 아래쪽 버튼이 A,
오른쪽 버튼이 B, 숄더 버튼이나 트리거가 L/R, Start가 Start, Back·View·Share가
Select입니다.

`파일 > 녹화 시작 (MKV)`와 `녹화 중지`로 `recordings` 폴더에 MKV 녹화를 남길 수 있습니다.
녹화 중에는 빨리 감기를 쓸 수 없습니다.

### 명령줄

실행 파일이 있는 폴더의 PowerShell에서 다음과 같이 실행합니다.

```powershell
.\gp32emu_win64.exe --bios "gp32166m.bin" --smc "game.smc"
.\gp32emu_win64.exe --fxe "homebrew.fxe"
.\gp32emu_win64.exe --fpk "homebrew.fpk"
```

`--jit`은 JIT 켜기, `--no-jit`은 끄기, `--no-audio`는 소리 출력 끄기입니다.
옵션 없이 넘긴 파일 경로는 SMC 이미지로 취급하므로 FXE/FPK에는 해당 옵션을 쓰세요.
경로에 공백이 있으면 따옴표로 감쌉니다. `--bios`로 지정한 경로는 `GP32emu.ini`에도 저장됩니다.

## RetroArch 설치

### PC와 Linux 휴대기기

1. RetroArch의 플랫폼과 아키텍처에 맞는 코어를 설정된 코어 폴더에 넣습니다.
   Linux AArch64 코어는 x86-64 PC용이 아닙니다.
2. `gp32emu_libretro.info`를 RetroArch의 **코어 정보 파일 폴더**에 넣습니다.
   코어 폴더와 정보 파일 폴더는 다를 수 있습니다.
3. BIOS를 RetroArch의 **시스템/BIOS 폴더**에 `gp32166m.bin` 이름으로 넣습니다.
   512 KiB 이하의 다른 이름 덤프도 인식합니다.
4. 코어 불러오기에서 GP32emu를 고른 뒤 콘텐츠 불러오기에서 게임을 엽니다.

휴대기기의 코어·정보·BIOS 폴더는 기기별로 다릅니다. 기존 RetroArch 설정을 덮어쓰지 말고
설정에 지정된 위치를 사용하세요. 게임 목록을 따로 관리하는 메뉴에서는 목록 새로고침이
필요할 수 있습니다.

Linux에서 현재 폴더의 코어를 명령줄로 불러오는 예입니다.

```sh
retroarch -L ./gp32emu_libretro.so "game.smc"
```

### Android

독립 실행 앱은 APK를 설치한 뒤 시작 화면에서 보유한 GP32 BIOS를 선택하고, **게임 추가**로
압축을 푼 `.smc`, `.fxe`, `.fpk`를 가져옵니다. 가져온 게임은 게임 목록에 쌓이며, 가장
최근 게임은 **이어하기** 버튼으로 바로 실행됩니다. 게임을 길게 누르면 복사본과 세이브를 삭제합니다.
화면 문구는 시스템 언어(한국어/영어)를 따릅니다.

게임 중 뒤로가기나 ≡ 버튼을 누르면 일시정지 메뉴가 열립니다. 계속하기, 상태 저장, 상태 불러오기,
처음부터 다시 시작, 터치 조작 표시/숨기기, 터치 진동, 선명한 픽셀(정수배 확대), 게임 목록, 정보,
종료를 고를 수 있습니다. 상태 저장은 게임마다 슬롯 3개를 씁니다.
터치 조작은 방향키와 A/B/L/R/Start/Select를 제공하고, 가로 화면에서는 화면 양옆으로
배치됩니다. 여러 버튼을 동시에 누를 수 있고, 회전·일시정지·화면 전환 시 입력은 해제됩니다.
터치를 꺼도 키보드와 게임패드는 사용할 수 있습니다. 키보드는 Windows 기본 배치와
같고, 게임패드는 방향키/왼쪽 스틱, A/B, L1/R1 또는 L2/R2, Start/Select를 사용합니다.
게임패드의 Mode/Menu 버튼이나 Start+Select 동시 누르기로 메뉴를 엽니다.
파일은 앱 내부로 복사되며 원본은 바뀌지 않습니다.
앱 삭제 시 가져온 파일, 세이브, 상태도 삭제됩니다. APK는 기존 개발용 키로 서명한 직접 설치용입니다.

RetroArch 앱의 아키텍처에 맞춰 ARM64 또는 ARMv7 코어를 선택합니다. 기기의 운영체제가
64비트여도 앱이 32비트라면 ARMv7 코어가 필요합니다. 앱에서 제공하는 로컬 코어 설치 기능으로
`gp32emu_libretro_android.so`를 설치한 뒤, 정보 파일과 BIOS를 앱에 설정된 폴더에 넣고
콘텐츠를 불러옵니다. 코어 설치 방법과 파일 접근 권한은 RetroArch 배포판에 따라 다릅니다.
Android RetroArch에서의 실행과 조작은 아직 확인되지 않았습니다.

### 조작

RetroPad 1번 포트를 사용합니다. 방향키, A/B, L/R, Start, Select는 각각 같은 이름의
GP32 버튼에 대응합니다. 실제 키보드·게임패드 배치는 RetroArch의 입력 설정과 리맵에서 바꿉니다.
위의 Windows 키보드 표는 독립 실행 프로그램에만 적용됩니다.

### 코어 옵션

RetroArch 빠른 메뉴의 코어 옵션에서 설정합니다.

| 옵션 | 동작 |
| --- | --- |
| Dynamic recompiler | 기본 켜짐. x86-64와 AArch64에서 JIT을 사용합니다. ARMv7에는 JIT이 없습니다. |
| Boot mode | 기본 `auto`. 아래의 SMC 부팅 설명을 참고하세요. |
| LCD persistence | 액정 잔상 효과. 기본 꺼짐. |
| Frame interpolation | 프레임 사이를 섞는 효과. 기본 꺼짐. |
| CPU speed | 기본 100%. 100/125/150/175/200/250/300% 중 선택합니다. |
| Fix game code bugs | 기본 켜짐. 어스토니시아 스토리 R의 음원 디코딩과 Pinball Dreams의 시작 시 음소거를 실행 중에 보정합니다. 롬 파일은 바꾸지 않습니다. |
| Fast loading | 기본 켜짐. 게임이 소리를 끄고 화면을 멈춘 채 카드에서 데이터를 많이 읽는 동안 CPU를 4배로 돌려 멈춤 시간을 줄입니다. |

`Fix game code bugs`와 `Fast loading`은 Windows 독립 실행 프로그램에서 항상 켜져 있으며
끄는 설정이 없습니다.

SMC의 `auto`는 BIOS가 있으면 우선 사용하고, BIOS가 없거나 BIOS 경로의 콘텐츠 로드에
실패하면 직접 부팅을 시도합니다. 다만 `GPMM/` 같은 자작 카드 구조는 기본 BIOS 실행기가
시작하지 못하므로 BIOS가 있어도 카드를 연결한 직접 부팅으로 전환합니다.
`require_bios`는 BIOS를 요구하고 직접 부팅으로 전환하지 않습니다.
`direct_hle`는 BIOS를 사용하지 않습니다. 자작 카드 자동 판별은 이 모드에서도 적용됩니다.

CPU speed는 소리 높이·타이머·화면 갱신 주기를 바꾸지 않고 게임에 주는 CPU 시간을 늘립니다.
느린 게임이나 로딩에 도움이 될 수 있지만 호스트의 CPU 사용량이 늘고 호환성에 영향을 줄 수
있습니다. 필요한 게임에서만 올리세요.

## 저장과 백업

### 게임 안에서 저장

게임 내 저장 위치와 형식은 각 게임이 결정합니다. 압축을 푼 `.smc`를 실행하면
**원본 카드 이미지는 수정하지 않습니다**. 실행 중 카드 읽기·쓰기는 평소처럼
동작합니다. Windows와 RetroArch는 카드 쓰기가 2초간 멈췄을 때 변경분을 자동으로
기록하며, 기록 시도 사이에는 최소 10초의 간격을 둡니다. 작업 스레드를 켠 빌드(기본값)는
디스크 기록을 백그라운드에서 처리하고, 게임을 일시정지·종료하거나 바꿀 때도 마지막
변경분을 저장합니다.
저장 실패 시 기존 파일과 아직 기록하지 못한 변경분을 유지하고 재시도합니다.
Windows는 원본 파일 이름에 `.gp32.sav`를 붙인 파일, 예를 들어 `game.smc` 옆의
`game.smc.gp32.sav`를 사용합니다. RetroArch는 저장 폴더에 `게임이름.gp32.sav`를
사용합니다. 저장 위치에는 쓰기 권한이 필요하고, 변경분은 정확히 같은 원본 `.smc`
위로만 불러옵니다. ZIP은 먼저 압축을 풀어 주세요. RetroArch가 저장 폴더를 제공하지
않으면 시스템 폴더를 사용합니다. 확장자를 뺀 파일 이름이 같은 게임은 저장 경로도
같으므로 서로 다른 저장 폴더를 사용하세요.

전체 카드 이미지가 담긴 저장 파일은 `.gp32.smc`든 `.gp32.sav`든 그대로 불러옵니다.
다음번 페이지 변경분 저장이 성공하면 그 파일을 대신하며, 기존 파일을 삭제하지 못하면
그대로 남습니다. 유효하지 않은 저장 파일이나 원본이 다른 변경분 파일은 덮어쓰지 않고
로드를 중단합니다.

Windows HLE 실행과 RetroArch의 일반 직접 부팅은 쓰기 가능한 카드 장치를 연결하지 않으므로
게임 내 저장을 보존하지 못합니다. RetroArch가 자동 판별한 자작 카드 직접 부팅은 카드를
연결하므로 카드 쓰기를 보존할 수 있습니다. 카드 저장이 없는 경로에서는 스테이트를 사용하세요.

저장 실패 알림이 나오면 최신 진행 상황이 파일에 남지 않았을 수 있습니다. 공간과 쓰기 권한을
확인하세요. 기존 저장 이미지가 읽히지 않으면 이를 보호하기 위해 게임 로드가 중단됩니다.
중요한 진행 상황이 담긴 카드 파일은 별도로 백업해 두세요.

### 세이브 스테이트

Windows에서는 F5로 현재 슬롯에 저장하고 F8로 불러옵니다. 슬롯은 1~9번이며 F6/F7이나
`파일 > 상태 슬롯`에서 바꿉니다. 파일은 `states` 폴더에 게임 파일 이름을 붙여
`game.smc.state1.gp32st`처럼 저장됩니다. 다른 위치에 저장하거나 불러오려면
`파일 > 다른 이름으로 상태 저장...`과
`파일 > 파일에서 상태 불러오기...`를 사용하세요. F12 스크린샷은 `screenshots` 폴더에
게임 이름과 시각이 붙은 BMP로 저장됩니다.
Android에서는 일시정지 메뉴의 상태 저장·불러오기에서 슬롯 3개 중 하나를 고릅니다.
RetroArch에서는 프런트엔드의 스테이트 저장·불러오기 기능을 사용합니다.

스테이트는 CPU·메모리·연결된 카드까지 포함하는 순간 저장입니다. 카드 변경분은
원본 기준으로 저장될 수 있으므로 해당 원본 ROM을 그대로 보관하세요. 스테이트를
불러오면 게임 내 저장 내용도 그 시점으로 돌아갑니다.

스테이트는 게임 내 저장 이미지와 별개입니다. 다른 빌드나 프런트엔드 사이의 스테이트 호환성은
보장하지 않습니다. 실제 RetroArch 세션에서의 되감기와 런어헤드는 미검증입니다.

## 문제 해결과 제한

- **BIOS 없이 시작 화면에서 멈춤:** BIOS를 지정해 실행하세요. Astonishia Story R, Hany,
  Super Plusha 등은 직접 부팅에 제한이 있습니다.
- **자작 카드가 DATA LOADING에서 멈춤:** RetroArch에서 `Boot mode`가 `auto`인지 확인하세요.
  자작 카드 자동 전환 설명은 RetroArch용이며 Windows 독립 실행에 그대로 적용되지 않습니다.
- **소리가 끊김:** 다른 무거운 프로그램을 닫고, 기기에서 성능 모드를 선택할 수 있으면 확인하세요.
- **어스토니시아 스토리 R 음악에 틱 잡음이 들림:** 이 보정은 기본으로 켜져 있습니다.
  RetroArch에서는 `Fix game code bugs` 옵션을 켜 두세요. Windows 독립 실행 프로그램은
  끄는 설정 없이 항상 적용합니다. 기존 스테이트에 이미 디코딩된 음원이 남아 있으면
  처음에는 잡음이 이어질 수 있습니다.
- **로딩 중 잠깐 멈춤:** 블루 안젤로의 대화창 로딩은 카드 읽기가 많아 느립니다. RetroArch에서
  `Fast loading`이 켜져 있으면 조건이 맞는 무음 로딩 구간이 줄어듭니다. Windows에서는 이
  기능이 항상 적용됩니다.
- **Pinball Dreams에서 소리가 없음:** RetroArch에서 `Fix game code bugs`를 켜 두세요.
  게임의 시작 시 DAC 음소거를 보정하며, 게임 안의 MUSIC·SFX 설정은 그대로 적용됩니다.
  MUSIC을 켰는지도 확인하세요.
- **저장되지 않거나 저장 이미지를 읽지 못함:** 위의 저장 위치, 여유 공간, 권한을 확인하세요.
  기존 저장 파일은 백업한 뒤 상태를 확인하세요.
- **RetroArch가 종료됨:** `retroarch --verbose`로 로그를 확인하세요.

호환성 확인은 일부 장면에 한정되며 전체 게임 완주를 보장하지 않습니다. 실제 GP32와의 소리·입력
지연 비교, 장시간 플레이는 미확인입니다. 실제 ARM Android 기기, Qt 실행, 브라우저 재생도 미검증입니다.
